# 类与函数说明

本文档用于辅助撰写 `README.md`，按项目模块整理主要类、函数职责和可在报告中使用的说明文字。

---

## 1. `core` 模块

`core` 模块负责游戏核心规则，包括棋盘数据结构、游戏流程、商店、战斗、羁绊、装备掉落、存档读档等。

---

## 1.1 `Board`

位置：`include/core/Board.h`，`src/core/Board.cpp`

### 类职责

`Board` 表示棋盘或备战区的数据结构。它维护每个格子上是否存在单位，并提供格子合法性判断、单位放置、移动、删除、邻居格计算和攻击范围计算等基础功能。

### 常量

| 名称 | 说明 |
|---|---|
| `ROWS` | 主棋盘行数，当前为 8 |
| `COLS` | 主棋盘列数，当前为 8 |

### 构造与析构

| 函数 | 说明 |
|---|---|
| `Board(int rows, int cols, bool isBoard)` | 创建棋盘或备战区。`isBoard == true` 表示主棋盘，`false` 表示备战区 |
| `~Board()` | 默认析构，不负责释放单位对象，只管理格子指针关系 |

### 基础操作

| 函数 | 说明 |
|---|---|
| `addUnit(Unit* unit, const QPoint& pos)` | 将单位加入指定格子，并同步单位自身坐标 |
| `removeUnit(Unit* unit)` | 从当前格子移除单位，不销毁单位对象 |
| `moveUnit(Unit* unit, const QPoint& pos)` | 将单位从原位置移动到新位置 |
| `getUnitAt(const QPoint& pos) const` | 获取指定格子上的单位指针，若无单位则返回 `nullptr` |
| `hasUnitAt(const QPoint& pos) const` | 判断指定格子是否存在单位 |
| `clear()` | 清空棋盘或备战区中保存的单位指针 |

### 棋盘计算

| 函数 | 说明 |
|---|---|
| `getNeighborGrid(const QPoint& pos) const` | 根据六边形棋盘规则获取相邻格子 |
| `getRangeGrid(const QPoint& pos, int range) const` | 获取某个位置指定攻击距离内的所有格子 |
| `isValidPosition(const QPoint& pos) const` | 判断坐标是否合法；主棋盘和备战区使用不同规则 |
| `isPlayerHalf(const QPoint& pos) const` | 判断位置是否位于玩家可部署半区 |

### 私有辅助函数

| 函数 | 说明 |
|---|---|
| `indexOf(const QPoint& pos) const` | 将二维坐标转换为一维数组下标 |

## 1.2 `Game`

位置：`include/core/Game.h`，`src/core/Game.cpp`

### 类职责

`Game` 是项目的核心控制类，负责连接游戏规则与图形界面。它管理棋盘、备战区、所有单位、玩家数据、商店、装备、羁绊、回合流程和战斗 tick，是游戏主逻辑的集中入口。

### 枚举

| 名称 | 说明 |
|---|---|
| `GamePhase::Prep` | 准备阶段，玩家可以购买、出售、拖拽布阵 |
| `GamePhase::Combat` | 战斗阶段，单位自动行动 |
| `GamePhase::Resolve` | 结算阶段，根据胜负更新玩家状态 |

### 构造与初始化

| 函数 | 说明 |
|---|---|
| `Game(int rows, int cols, QObject* parent = nullptr)` | 创建游戏对象，初始化棋盘、备战区、场景、计时器和基础数据 |
| `~Game()` | 释放游戏中创建的单位和相关资源 |
| `initialize()` | 初始化一局游戏，建立场景、生成单位和敌人，并连接计时器 |
| `startNewGame()` | 开始新游戏，重置玩家、棋盘、单位、商店等状态 |

### 数据访问接口

| 函数 | 说明 |
|---|---|
| `getScene() const` | 返回 Qt 图形场景，用于 `QGraphicsView` 显示 |
| `getUnitById(int unitId) const` | 根据单位 id 查找 `Unit` |
| `getUnitItem(int unitId) const` | 根据单位 id 查找对应的图形对象 |
| `getGridItem(const QPoint& gridPos) const` | 获取指定格子的图形对象 |
| `getPlayer() const` | 返回玩家数据对象 |
| `getPlayerUnitInBoard() const` | 返回当前上阵的己方单位数量 |
| `getActivateSynergyList() const` | 返回当前已激活或接近激活的羁绊显示文本 |
| `getRaceName(Race race) const` | 将种族枚举转换为显示文本 |
| `getProName(Profession pro) const` | 将职业枚举转换为显示文本 |
| `getPhase() const` | 获取当前游戏阶段 |
| `getEquipmentItem(int index) const` | 获取指定装备槽中的装备图形对象 |
| `getEquipmentSlotFull()` | 判断装备栏是否已满 |
| `getSynergyDes(Race race, Profession pro)` | 获取指定种族或职业羁绊的说明文本 |

### 回合与经济系统

| 函数 | 说明 |
|---|---|
| `startNxtRound()` | 进入下一回合，清理旧敌人、恢复玩家单位、生成新敌人 |
| `buyXp()` | 消耗金币购买经验，推动玩家等级和人口上限提升 |
| `rollShop()` | 随机生成 5 个商店英雄 |
| `buyHero(int gold, QString name)` | 购买商店英雄，将其加入备战区 |
| `sellHero(Unit* unit)` | 出售英雄，返还金币，并处理其身上的装备 |
| `upUnitStar(QString name, int star)` | 检查是否存在 3 个同名同星英雄，若满足则合成为高星英雄 |

### 暂停与存档

| 函数 | 说明 |
|---|---|
| `pauseGame()` | 暂停战斗计时器 |
| `resumeGame()` | 恢复战斗计时器 |
| `saveGame()` | 将玩家状态、单位状态、装备状态写入文本存档 |
| `LoadGame()` | 从文本存档中恢复游戏状态 |

## 2.3 英雄子类

位置：`include/entity/Heroes.h`，`src/entity/Heroes.cpp`

### 类职责

所有英雄类都继承自 `Unit`，通过重写 `castSkill()` 实现不同技能，通过重写 `updateUnit()` 或 `takeDamage()` 实现特殊状态和 Boss 阶段变化。这体现了 PA 要求中的继承与多态设计。

### 英雄通用接口

| 函数 | 说明 |
|---|---|
| `构造函数` | 设置英雄基础属性、阵营、星级、职业、种族等 |
| `castSkill(Board& board, const std::vector<Unit*> allUnits)` | 实现英雄主动技能 |
| `takeDamage(int atk)` | 可选重写，用于减伤、阶段转换等特殊受击机制 |
| `updateUnit(Board& board, const std::vector<Unit*> allUnits)` | 可选重写，用于持续技能、Debuff、Boss 机制等 |
| `getSkillDes() const` | 返回技能说明 |
| `getClassName() const` | 返回类名或英雄标识 |

## 4. 适合 README 中总结的设计点

### 4.1 面向对象设计

- `Unit` 作为抽象基类，统一保存单位属性和战斗状态机。
- 每个英雄继承 `Unit`，通过重写 `castSkill()` 实现不同技能。
- Boss 通过重写 `takeDamage()`、`updateUnit()` 等函数实现阶段机制。
- GUI 图元类与数据类分离，`UnitItem` 负责显示，`Unit` 负责规则数据。

### 4.2 状态机设计

单位每帧由 `Game::gameTick()` 驱动，调用 `Unit::updateUnit()`。单位内部根据 `State` 在 `Idle`、`Moving`、`Attacking`、`Casting`、`Dead` 之间切换，使自动战斗逻辑清晰可控。

### 4.3 Qt 信号槽设计

- `UnitItem` 将点击和拖拽转换为信号，交给 `Game` 处理规则。
- `Unit` 在属性变化、死亡和受伤时发出信号，通知 UI 更新。
- `Game` 在回合结束、游戏结束、战斗状态变化时发出信号，通知窗口和面板刷新。

### 4.4 核心算法

- `Board::getNeighborGrid()` 实现六边形棋盘邻接计算。
- `Board::getRangeGrid()` 根据邻接扩展计算攻击范围。
- `Unit::breadFirstSearch()` 使用 BFS 进行寻路。
- `Game::calculateSynergies()` 统计场上单位种族和职业，并触发羁绊 Buff。

### 4.5 数据流概括

1. 玩家在 `GameWindow` 中点击商店、拖拽单位或开始战斗。
2. GUI 事件通过信号传递给 `Game`。
3. `Game` 修改 `Board`、`Unit`、`Player` 等核心数据。
4. 核心数据变化后再通过信号通知 `UnitItem`、`InfoPanel`、`SettlementPanel` 等界面刷新。
